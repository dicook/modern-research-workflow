Before you arrive: getting set up

A Modern Research Workflow with R and GitHub

Welcome, and thank you for joining us. 🫶

To make the most of our time together, we ask you to set up your laptop before the workshop. It takes about 40 minutes and you only do it once. Nothing here is hard: it is mostly downloading, clicking “Next”, and signing in.

TipStuck? You are not alone

Software installs can be fiddly, and that is completely normal. If any step does not work, stop, make a note of what happened, and seek help. The 30 minutes prior to the workshop are set aside for setup help. You can also email the organisers with a screenshot of the problem that you are encountering, in the day prior to the workshop.

Step 1: Create a GitHub account (5 minutes)

GitHub is the website where we will store and share our projects.

  1. Go to github.com/signup
  2. Enter your email, choose a password and a username
  3. Check your inbox and verify your email address
NoteChoosing a username

Pick something you will be happy to put on a CV or paper for years, such as firstname-lastname. Already have an account? Brilliant, you can skip ahead 🏃🏾‍♀️‍➡️ and just make sure you can sign in.

GitHub may ask you to set up two-factor authentication. Follow the prompts (the Github app for you phone, an authenticator app or a passkey all work) and save your recovery codes somewhere safe.

Step 2: Install R (5-10 minutes)

R is the programming language we will use.

  1. Go to cran.r-project.org
  2. Click the link for your system (Windows or macOS)
  3. Windows: choose base, then “Download R for Windows”. macOS: pick the installer that matches your Mac (Apple silicon for M1 and newer, Intel otherwise)
  4. Open the downloaded file and accept the default options

TipNot sure which Mac you have?

Click the Apple menu, then About This Mac. If it says “Chip: Apple M…” choose Apple silicon. If it says “Processor: Intel”, choose Intel.

If you already have R, please make sure it is a recent version (the one listed at the top of the CRAN page, or close to it).

Step 3: Install RStudio or Positron (5 minutes)

This is the program where you will write and run your R code. Install R first, then one of these:

  • RStudio Desktop (choose this if you are unsure)
  • Positron (a newer option, which we will use for demonstration)

Open it once to check it starts. You should see a window with a console where you can type R code.

Step 4: Install Git (5 minutes) (Optional but recommended)

Git is the tool that keeps the history of your files. GitHub Desktop has its own copy inside it, but R and RStudio need Git installed separately.

If you install GitHub Desktop (step 5) it comes with a version of Git, so you can skip this step. However, it will mean that all Git use will need to be through GitHub Desktop. This is almost always adequate.

  • Windows
  • macOS
  1. Download from git-scm.com/downloads
  2. Run the installer and click Next through the questions. The defaults are fine
  1. Open the Terminal app (press Cmd + Space and type “Terminal”)
  2. Type git --version and press Enter
  3. If Git is missing, your Mac will offer to install the “command line developer tools”. Click Install and wait for it to finish

Step 5: Install GitHub Desktop and shake hands with GitHub (5-10 minutes)

GitHub Desktop is a friendly app for saving and sharing your work. This step also introduces your laptop to your GitHub account, and you only need to do it once.

Install it

  1. Download GitHub Desktop and run the installer

Sign in (the handshake)

  1. Open GitHub Desktop and click Sign in to GitHub.com
  2. Your web browser opens. Sign in to GitHub and click Authorize
  3. Your browser sends you back to GitHub Desktop, which now shows your username

Tell Git who you are

  1. Open the settings: on Windows, File > Options. On macOS, GitHub Desktop > Settings
  2. Go to the Git tab and enter your name and your email. Use the same email as your GitHub account
NoteAbout email privacy

Your email is attached to the changes you save. If you would rather keep it private, the Git tab lets you choose your GitHub “noreply” address instead. Either is fine for the workshop.

Step 6: Install the R packages (5-10 minutes)

Packages are add-ons that give R extra abilities. Open RStudio (or Positron), click in the Console, paste the code below and press Enter.

pkgs <- c("usethis", "here", 
          "ggplot2", "readr", "tibble",
          "quarto", "rmarkdown", "knitr", 
          "fs")

install.packages(pkgs)

Lots of text will scroll past, which is normal. A few tips:

  • It can take several minutes. Wait for the > prompt to come back
  • If asked “Do you want to install from sources?”, type No and press Enter
  • If asked to restart R, say Yes

Step 7: Install TinyTeX for PDF articles (5-10 minutes)

Journal articles are usually turned into a PDF, and for that Quarto needs a behind-the-scenes tool called LaTeX. TinyTeX is a small, friendly version of it. You only install it once and never need to open it yourself.

NoteAlready have LaTeX?

If you already use MacTeX, MiKTeX or TeX Live, you can skip this step, just check that the test below works.

In the RStudio (or Positron) Console, paste:

install.packages("tinytex")
tinytex::install_tinytex()

It downloads a few hundred megabytes, so give it a few minutes and wait for the > prompt to come back. If you are asked to restart R, say Yes.

Quick test. Create a new Quarto document (File > New File > Quarto Document), replace everything in it with the text below, save it, and click Render:

---
title: "Test"
format: pdf
---

Hello, PDF!

A PDF with “Hello, PDF!” means you are ready. The first render can take a few minutes while LaTeX fetches a few extras, so please be patient. After that it is much faster.

WarningTinyTeX did not work? Try this instead

You only need one LaTeX installation. If TinyTeX failed, use the option for your computer below. Then restart RStudio (or Positron) and run the test document from the step above.

  • Windows
  • macOS

Install MiKTeX.

  1. Download the installer from miktex.org/download and run it
  2. Choose Install for: only me if you do not have administrator rights
  3. When asked about missing packages, set Install missing packages on-the-fly to Yes. If you skipped this, open MiKTeX Console, go to Settings > General, and set it there
  4. Restart RStudio and render the test document. The first render can take several minutes while MiKTeX downloads extras

Install MacTeX.

  1. Download from tug.org/mactex. It is a large download (several GB), so start it on a good connection
  2. Open the downloaded .pkg file and click through the installer with the default options
  3. Restart RStudio and render the test document

If both TinyTeX and your new install are present and you see odd errors, you can remove TinyTeX by running tinytex::uninstall_tinytex() in the Console, then restart.

Still stuck? Skip PDF for now. The workshop will work with HTML output, and we can help you in the first 15 minutes.

Step 8: Final check (2 minutes)

Paste this into the Console. It tells you whether everything is ready.

# 1. Are all the packages installed? We want to see: character(0)
setdiff(pkgs, rownames(installed.packages()))

# 2. Does Git know who you are? We want to see your name and email
usethis::git_sitrep()

# 3. Is Quarto available? We want to see a file path
quarto::quarto_path()
ImportantWhat a good result looks like
  1. character(0) means every package is installed
  2. usethis::git_sitrep() lists your name and email
  3. A file path means Quarto was found. If you see NULL, install it from quarto.org/docs/get-started

If all three look right, you are ready. 🎉 Take a screenshot if you like, and see you at the workshop!

Optional: connect R to GitHub as well

We will mostly use GitHub Desktop, so this is not required. If you would like to push to GitHub directly from R, you can also create a personal access token (a password-like code for R):

usethis::create_github_token()   # opens GitHub in your browser, click "Generate token"
gitcreds::gitcreds_set()         # paste the token when asked
